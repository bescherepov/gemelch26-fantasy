# AGENTS.md — инструкции для агента

## 1. Что это за проект

Сайт-хроника текстовой партии «Гегемония» о мире Расфадаль (900–910 гг.).
Живой сайт: <https://bescherepov.github.io/gemelch26-fantasy/>

- Стек: **Python 3.9+ (только стандартная библиотека) + HTML/CSS/vanilla JS**.
- Никаких npm, сборщиков, фреймворков и внешних Python-пакетов.
- Контент, комментарии и коммиты — **на русском**.
- Публикация — GitHub Actions → GitHub Pages при пуше в `main`.

Полная архитектура — в [CONCEPT.md](CONCEPT.md), быстрый старт — в [README.md](README.md).

Текущее состояние: 3 хода, 36 событий, 9 народов, 4 карты, 10 страниц, 34 теста.

---

## 2. Главный принцип: единый источник информации

`data/*.json` — единственное место, где живёт игровой контент. Всё остальное
(`templates/`, `dist/`, страницы, статистика, лог) — производное.

Правила, которые нельзя нарушать:

1. **Контент — только в `data/`.** Не вписывать события, имена и даты в шаблоны,
   CSS или JS. В шаблонах допустим только интерфейсный текст («Ходы», «Фильтр»).
2. **`dist/` не редактируется и не коммитится.** Он пересоздаётся при каждой сборке.
3. **Один факт — одна запись.** Событие описано только в своём ходе; карта — только
   в `data/maps.json`; таблица — только в `data/tables.json`.
4. **Ссылки на файлы, а не копии.** В данных — путь к изображению, сам файл лежит
   в `assets/img` один раз.
5. **Только проверяемые факты.** Источники: `sources/*.docx`, хроника мастера на
   DM.AM, присланные карты. Не додумывать имена, титулы, даты и исходы битв.
6. **Технические правки не попадают в лог.** Лог — про игровые данные, не про вёрстку.

## 4. Модель данных

### 4.1 Файлы

| Файл | Что описывает | Обязательные поля |
| --- | --- | --- |
| `site.json` | сайт и меню | `title`, `subtitle`, `description`, `base_url`, `lang`, `menu[]` |
| `world.json` | мир | `title`, `lead`, `intro[]`, `facts[]`, `regions[]`, `laws[]` |
| `history.json` | летопись | `epochs[].id/number/title/years/blocks[]` |
| `ethnoses.json` | народы | `ethnoses[].id/name/color/epithet/analog/geography/description` |
| `turns/NNN.json` | ход | `number`, `year`, `title`, `lead`, `events[]` |
| `maps.json` | карты | `categories[]`, `maps[].id/category/title/caption/file` |
| `tables.json` | таблицы | `tables[].id/title/file` |
| `participants.json` | рассадка | `title`, `intro`, `count`, `image`, `notes[]` |
| `links.json` | ссылки | `links[].id/title/url/description` |
| `changelog.json` | лог | `entries[].date/text` |

### 4.2 Схема хода

```json
{
  "number": 3,
  "year": 910,
  "title": "Кашшу",
  "lead": "В мире появляется первая организованная религия…",
  "map": {
    "image": "assets/img/map-political-905.png",
    "caption": "Политическая карта после 2-го хода (905 г.)"
  },
  "note": "Карта 3-го хода публикуется в хронике мастера.",
  "events": [
    {
      "type": "religion",
      "title": "Кашшу",
      "text": "Деятельность расфадальского священника Линуса Даре…"
    }
  ]
}
```

`map` и `note` могут быть `null`. Событий — минимум одно.

### 4.3 Типы событий

Закрытый список (ключ → подпись): `politics` → Политика, `war` → Война,
`diplomacy` → Дипломатия, `dynasty` → Династия, `religion` → Религия,
`disaster` → Катастрофа, `economy` → Экономика, `city` → Город,
`culture` → Культура, `migration` → Переселение.

Новый тип добавляется в трёх местах: `TYPE_LABELS` в `build.py`, CSS-класс
`.badge--<тип>` в `assets/css/style.css` и (при желании) цвет в палитре бейджей.

### 4.4 Что проверяет валидатор

- номера ходов идут подряд с 1, годы возрастают и не повторяются;
- у события известный тип, непустые `title` и `text`;
- `id` уникальны (народы, эпохи, карты, таблицы, ссылки);
- цвета в формате `#rrggbb`;
- все упомянутые изображения существуют;
- категории карт объявлены;
- даты лога в формате `ГГГГ-ММ-ДД`;
- пункты меню ведут на реально собираемые страницы.

## 5. Типовые задачи

### Добавить ход

1. Положить карту в `assets/img/map-<тип>-<год>.png`.
2. Добавить запись в `data/maps.json` (уникальный `id`, категория, подпись, файл).
3. Создать `data/turns/<год>.json` по образцу соседнего хода.
4. Проверить: `python scripts/validate.py`.
5. Собрать: `python build.py`.
6. Полный прогон: `python -m unittest discover -s tests` и
   `python scripts/validate.py --dist`.
7. Коммит на русском: `Добавлен 4-й ход (915 г.)`.
8. Пуш в `main` — сайт опубликуется сам.

### Добавить карту или таблицу

Запись в `data/maps.json` или `data/tables.json` + файл в `assets/img`.
Страницы, галерея и превью на главной обновятся автоматически.

### Добавить народ

Запись в `data/ethnoses.json` с уникальным `id` и каноническим цветом.
Карточка, список на главной и раздел «Этносы» появятся сами.

### Исправить текст

Правка одной строки в JSON, без изменений в шаблонах.

### Сменить обложку

`hero_map` выбирается в `build.py` по `id` карты (`political-905`); достаточно
добавить карту с нужным `id` или изменить выбор в одном месте.

## 6. Лог изменений

`scripts/changelog.py` собирает записи из `git log -- data` и сливает их с
курируемыми в `data/changelog.json`.

- В лог попадают только коммиты, менявшие `data/`, — то есть игровые изменения.
- Сообщение коммита = будущая запись лога. Писать кратко и по-русски:
  `Добавлен 4-й ход (915 г.)`, `Обновлена политическая карта`.
- Технические коммиты (вёрстка, тесты, документация) не трогают `data/` и потому
  в лог не попадают.
- Merge/revert/WIP пропускаются; коммит, создающий `data/site.json` (первичная
  публикация), тоже пропускается.
- Результат в репозиторий не коммитится: файл дополняется в CI перед сборкой.

## 7. Сборка и проверки

```bash
python scripts/validate.py            # данные
python -m unittest discover -s tests  # 34 теста движка и сборки
python build.py                       # dist/
python scripts/validate.py --dist     # ссылки, якоря, h1, meta
python -m http.server 8000 -d dist    # локальный просмотр
```

Порядок в CI (`.github/workflows/pages.yml`):
`validate` → `tests` → `changelog` → `build` → `validate --dist` → deploy.

**Definition of Done** для любой правки:

- [ ] данные изменены только в `data/` (или это осознанная правка шаблона/кода);
- [ ] `validate.py` без ошибок;
- [ ] тесты зелёные;
- [ ] `validate.py --dist` без битых ссылок;
- [ ] в собранном HTML нет `{{` и `{%`;
- [ ] новая логика покрыта тестом (если менялся код, а не только данные);
- [ ] коммит по-русски, по существу;
- [ ] пуш в `main`, workflow завершился успешно.

## 8. Git и публикация

- Сообщения коммитов — русские, краткие, в повелительном/прошедшем стиле:
  `Добавлен 2-й ход`, `Исправлена подпись карты`.
- `dist/` в `.gitignore` — не коммитить и не пушить.
- Пуш в `main` разрешён и является штатным способом публикации.
- Pages настроен на источник **GitHub Actions**; `base_url` в `data/site.json`
  должен оставаться `https://bescherepov.github.io/gemelch26-fantasy/`.
- Проверить деплой: `gh run list --limit 1` или вкладка Actions.
- Секреты и токены в репозиторий не попадают: деплой идёт через OIDC.

## 9. Соглашения по коду

### Python

- Только стандартная библиотека. Новые зависимости не добавлять.
- Отступы — 4 пробела, имена — `snake_case`, комментарии — по-русски.
- Ошибки данных — через `fail()` в `build.py` или сообщения `validate.py`,
  с указанием файла и поля.
- `build.py` детерминирован: без сети, случайности и текущего времени в контенте
  (дата сборки — только в подвале и sitemap).

### Шаблоны

Поддерживаемый синтаксис движка: `{{ … }}`, `{{ … | safe }}`,
`{% for %}…{% endfor %}` (+ `loop.index/first/last/length`), `{% if %}/{% elif %}/{% else %}`,
`{% include "file.html" %}`, фильтры `date_ru`, `join`, `default`, `length`, `upper`,
`lower`, `number`.

- Автоэкранирование включено; `| safe` — только для готового HTML (`content`, JSON-LD).
- Обращение к несуществующему ключу в `{{ }}` — ошибка сборки, это нормально:
  так ловятся опечатки.
- Одна страница — один `<h1>`; секции — с заголовками; изображения — с `alt`.
- Контент должен читаться без JavaScript: скрытие ходов включает класс `js` на `<html>`.

### CSS

- Токены в `:root` (`--olive`, `--amber`, `--paper`, `--serif`…), палитра старого сайта.
- Имена классов — BEM-подобные (`.turn__head`, `.turn-tab__year`).
- Брейкпоинты: 980px (раскладка), 900px (меню), 640px (мобайл).
- Никаких CSS-фреймворков и внешних шрифтов.

### JavaScript

- Vanilla, без зависимостей; стиль совместимый (var/function), без сборки.
- Только прогрессивное улучшение: переключение ходов, поиск, фильтры, меню.
- Новые фичи обязаны деградировать без JS (контент остаётся доступным).

## 10. Чего не делать

- Не добавлять npm/pip-зависимости и сборщики.
- Не редактировать `dist/` и не коммитить его.
- Не дублировать контент в шаблонах, CSS и JS.
- Не выдумывать факты, имена, даты и исходы событий.
- Не менять порядок исторических событий без источника.
- Не отключать и не ослаблять валидатор/тесты ради «зелёного» CI.
- Не ломать работу без JavaScript и мобильную вёрстку.
- Не менять `base_url`, `menu` и структуру данных без необходимости.
- Не удалять `sources/` и тесты.
