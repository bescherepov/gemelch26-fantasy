# Расфадаль. Мир. Хроника

**Сайт:** <https://bescherepov.github.io/gemelch26-fantasy/>

Сайт-хроника партии «Гегемония» (900–915 гг.), собранный по принципу **единого источника информации**: весь контент описан в `data/*.json`, страницы генерируются скриптом, публикация — через GitHub Actions на GitHub Pages.

Полное описание архитектуры — в [CONCEPT.md](CONCEPT.md).

## Что умеет сайт

- мир, девять народов, летопись 400–900 и законы Айзенвелла;
- ходы 900 / 905 / 910 / 915 / 920 / 925 / 930 с картами, фильтром по типам событий и поиском по всей хронике;
- переходы между ходами, статистика событий, карты и таблицы с фильтрами;
- справочник построек: 137 карточек с поиском, разделами и местными правилами партии;
- лог изменений, который собирается из истории git;
- адаптивная вёрстка, работа без JavaScript, статический 404 и sitemap.

## Быстрый старт

Нужен только Python 3.9+ (никаких пакетов, npm и сборщиков).

```bash
python build.py                       # собрать сайт в dist/
python scripts/validate.py            # проверить данные
python scripts/nuke_audit.py         # проверить контракты и якоря NUKE
python -m unittest discover -s tests  # тесты движка, сборки, журнала и стандарта
python -m http.server 8000 -d dist
```

Журнал сборки для сверки траектории (Log Driven Development):
`NUKE_LOG=build-log.jsonl python build.py`, затем
`python scripts/nuke_audit.py --log build-log.jsonl`. Без `NUKE_LOG` журнал выключен и вывод не меняется.

Откройте <http://localhost:8000>.

## Что внутри

| Путь | Назначение |
| --- | --- |
| `data/` | Единственный источник правды: мир, народы, история, ходы, карты, постройки, ссылки |
| `data/turns/*.json` | По одному файлу на ход |
| `templates/` | HTML-шаблоны (движок — `engine.py`, без зависимостей) |
| `assets/` | CSS, JS и изображения |
| `build.py` | Генерация `dist/` |
| `nuke_log.py` | Журнал операций JSONL для Log Driven Development |
| `nuke/graph.yaml` | Граф архитектуры NUKE (единственный внешний артефакт) |
| `scripts/validate.py` | Проверка данных и ссылок |
| `scripts/changelog.py` | Дополнение лога из истории git |
| `scripts/nuke_audit.py` | Аудит стандарта: контракты, якоря, граф, тесты, логи |
| `tests/` | Тесты движка, сборки, журнала и стандарта NUKE |
| `sources/` | Исходники от мастера: Setting.docx и тексты ходов |
| `.github/workflows/pages.yml` | CI/CD: проверка → тесты → сборка → публикация |

## Как добавить ход

1. Положите карту в `assets/img/` и добавьте запись в `data/maps.json`.
2. Создайте `data/turns/920.json` по образцу соседнего хода.
3. Запустите `python scripts/validate.py`, `python -m unittest discover -s tests` и `python build.py`.
4. Закоммитьте изменения: `Добавлен 4-й ход (915 г.)`.

Лог изменений собирается автоматически из коммитов, которые трогают `data/`. Переходы между ходами, статистика, навигация и поиск пересоберутся сами.

## Стандарт NUKE

Код размечен по [NUKE.md](NUKE.md) (NUKE 2.0): у каждого модуля есть `MODULE CONTRACT`
в шапке, у публичных символов — контракты с `PURPOSE`/`INPUTS`/`OUTPUTS`/`ERRORS`/
`KEYWORDS`/`TESTS`, правки адресуются якорями `START_BLOCK_*`/`END_BLOCK_*`,
а архитектура описана в `nuke/graph.yaml`. Аудит `python scripts/nuke_audit.py`
проверяет соответствие (C1–C10 из §16) и запускается в CI перед публикацией.
Внешние `.md` с описанием кода не ведутся: контракт живёт в коде.

## Публикация

Пайплайн уже настроен: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Каждый пуш в `main` пересобирает и публикует сайт. Pull request получает собранный артефакт `site-preview` без публикации.
